分库分表后: sql解析 -> 查询优化 -> sql路由 -> sql改写 -> sql执行 -> 结果归并
                                分片路由  带上条件的路由 select * from user where < user_id % 2 = 0 >
                                广播路由  查多有数据 select * from user


原则上能不分就不分

分库分表后的问题 跨库查询，跨库排序，分布式事务，公共表，主键重复
1. 事务一致性
    数据被分在不同的库，甚至是不同的服务器中
2. 跨节点关联查询
    表被分散到了不同的数据库中，无法关联查询
3. 跨节点分页，排序
    user表为单又分片，查询出的数据如何进行排序，分页的拼接
4. 主键的避重
    为保证唯一性，需要单独设计全局的主键
5. 公共表处理
    每个数据库中都保存一份高频联合查询的表
6. 聚合查询
    count order by
7. 运维工作量

全局唯一主键
1. 雪花算法  时间戳趋势递增友好
    64位的整数 = 1bit符号位, 41bit时间戳, 10bit机器id, 12bit序列号
                          可用69年     1024个节点   4096个序列号
2. UUID 最大的问题是无序的，会造成b树反复重建索引

总结 分库分表的决策原则
1. 优化sql, 索引
2. 加缓存 redis
3. 读写分离 (主从复制)
4. 归档低频老旧数据
5. 分库分表
