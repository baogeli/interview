# 小区停车计费管理系统 — 技术栈总结

## 项目概况

小区停车计费管理系统，一个采用**微服务架构**的 Go 语言落地项目，代码约 **381 个 `.go` 文件**，编译后部署为 **9 个独立二进制服务**。

---

## 技术栈与亮点

### 1. 微服务架构 & 服务拆分

项目拆分为 **9 个独立服务**，每个服务有独立的 `config`、`core`、`global` 模块，独立编译部署：

| 服务 | 文件数 | 职责 |
|------|--------|------|
| api | 52 | 后台管理 + 保安端 API 服务 |
| server | 83 | 设备控制与道闸交互服务 |
| db | 78 | 数据库 gRPC 服务层 |
| bill | 19 | 独立计费微服务 |
| websocket | 14 | 实时消息推送服务 |
| cloud | 39 | 云端管理服务 |
| rtsp | 11 | 视频流接入服务 |
| tcpClient / tcpServer | 2 | 设备 TCP 长连接通信 |

### 2. gRPC + Protocol Buffers

- 定义了 **8 个 proto 文件**（约 4000 行），涵盖数据库查询、计费、设备控制、WebSocket 消息、进出场、交接班等场景
- 服务间通过 **gRPC 客户端调用** 通信，配置了 Keepalive 保活机制
- 使用 `protoc-go-inject-tag` 做结构体标签注入
- 核心依赖：`google.golang.org/grpc v1.65.0`

### 3. RESTful API & JWT 鉴权

- 基于 **Gin** 框架提供 RESTful API，覆盖管理员、保安端两套体系
- **JWT 中间件鉴权**，区分管理员/保安角色权限
- **RBAC 权限模型**：用户-角色-菜单三级权限控制
- 支持 CORS 跨域、HTTPS 可选
- 核心依赖：`gin-gonic/gin v1.8.1`、`dgrijalva/jwt-go v3.2.0`

### 4. GORM + 多数据库

- **GORM v1** 作为 ORM，支持 **MySQL + SQLite** 双引擎
- 15+ 数据模型：车辆、通道、硬件设备、订单、优惠券、进出场记录、收费规则等
- 支持 Excel 导入/导出（`excelize`）
- 核心依赖：`gorm.io/gorm v1.25.2`、`gorm.io/driver/mysql v1.3.4`、`glebarez/sqlite v1.9.0`

### 5. 复杂计费引擎

- 计费逻辑集中在 `bill` 微服务和 `cal_func` 包中
- 支持多种计费模式：**按时段计费、按天计费、分时段模式（segmented）、夜间/白天差异化**
- 支持优惠券、商户活动、模拟计费调试
- 核心依赖：`golang-module/carbon v1.7.1`（时间处理）

### 6. WebSocket 实时通信

- 基于 **gorilla/websocket** 实现实时推送
- **Hub 模式** 管理多用户连接，支持按频道/分组广播
- 实时推送进出场状态、闸机状态到保安端和监控大屏
- 核心依赖：`gorilla/websocket v1.4.2`

### 7. RTSP 视频流 & WebRTC

- **rtsp** 服务接入摄像头 RTSP 流
- 基于 **pion/webrtc**（WebRTC 纯 Go 实现）将视频流推送到浏览器
- 支持视频抓拍、车牌识别后的图片处理
- 核心依赖：`deepch/vdk v0.0.19`、`pion/webrtc/v3 v3.1.42`

### 8. 设备交互 & IoT 协议

- **TCP 长连接** 与道闸硬件设备通信（`net` 标准库）
- **485 串口** 通信控制 LED 播报板
- **KCP 可靠 UDP**（kcp-go）优化弱网环境下的设备通信
- 设备模型：门禁控制器、LED 屏、抓拍相机、道闸等
- 核心依赖：`kcp-go v2.0.4`、`pion/udp v0.1.1`

### 9. 配置管理 & 日志

- **Viper** 统一配置管理，支持 YAML 配置文件热加载（`fsnotify`）
- **Uber Zap** 高性能日志库，按级别分类记录
- 每个模块独立的 `config_*.yaml` 配置文件
- 核心依赖：`spf13/viper v1.8.1`、`uber-go/zap v1.19.0`

### 10. 构建与部署

- Shell 脚本自动化构建（`build.sh`），一条命令编译全部 9 个服务
- **交叉编译**：`CGO_ENABLED=0 GOOS=windows GOARCH=amd64`
- **FRP** 内网穿透部署
- 输出 ZIP 包发布，包含配置文件 + 前端资源

### 11. 其他技术点

- **Prometheus** 监控指标集成
- **Cobra + Viper** CLI 命令框架
- **Carbon** 时间处理库，处理停车时长计算
- **go-socks5** SOCKS5 代理支持
- **testify** 单元测试框架

## 简历中的推荐写法

> - 基于 **Gin + GORM** 构建 RESTful API，实现 JWT 鉴权与 RBAC 三级权限管理
> - 设计复杂计费引擎，支持按时段/按天/分时段/夜间差异化等多种计费策略，含优惠券体系
> - 基于 **gorilla/websocket** Hub 模式实现实时消息推送，覆盖监控大屏、保安端、进出场状态同步
> - 集成 **RTSP + WebRTC（pion）** 实现摄像头视频流接入与浏览器端实时观看
> - 通过 **TCP/KCP 长连接** 与道闸、LED 播报板等硬件设备通信
> - 使用 **Viper + Zap** 实现统一配置管理与高性能日志，Shell 脚本自动化构建与交叉编译部署

### 详细版（适合技术面试时展开）

> **小区停车计费管理系统（Go / gRPC / Gin / GORM）**
>
> **项目背景**：面向住宅小区的车辆进出管理与停车费计费系统，管理车辆、通道、硬件设备、订单等核心业务，支持管理员后台与保安端双操作体系。
>
> **架构设计**：
> - 微服务拆分，9 个独立服务（API 网关、设备控制、计费、数据库、WebSocket、云端管理、RTSP 视频流等），各服务独立配置与部署，通过 gRPC 跨服务调用
> - Proto 定义 8 个服务接口（约 4000 行），涵盖数据库 CRUD、计费计算、设备控制、实时消息、进出场、交接班
>
> **核心技术**：
> - 后端 API：Gin 框架 + JWT 鉴权 + RBAC 权限（用户-角色-菜单三级），支持管理员与保安端双角色路由
> - 数据层：GORM ORM + MySQL/SQLite 双引擎，15+ 数据模型，Excel 导入导出
> - 计费引擎：多策略计费（按时段/按天/分时段/夜间差异化），优惠券体系，支持模拟计费调试
> - 实时通信：gorilla/websocket Hub 模式，按频道分组广播，实时推送进出场状态与闸机事件
> - 视频流：RTSP 接入摄像头 → pion/webrtc 转码 → 浏览器端实时播放
> - 硬件通信：TCP 长连接 + KCP 可靠 UDP 与道闸/LED 屏通信，485 串口控制播报板
> - 基础设施：Viper 配置管理 + fsnotify 热加载、Zap 高性能日志、Prometheus 监控、Cobra CLI
>
> **构建部署**：Shell 脚本一键编译 9 个服务，支持交叉编译（Windows amd64），FRP 内网穿透，ZIP 包发布（含前端资源与配置文件）
>
> **技术栈**：Go 1.21+ / Gin / GORM / gRPC + Protobuf / gorilla/websocket / pion/webrtc / Viper / Zap / Prometheus / kcp-go / MySQL
